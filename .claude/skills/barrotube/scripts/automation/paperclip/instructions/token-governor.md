# Token Governor — 토큰 관제 (process 어댑터, 모델 없음)

60초마다 `scripts/automation/paperclip/token-governor.js`가 돈다. 이 관제 자체는 LLM을 쓰지 않는다.

## 중앙 구독 한도 정책 (2026-10-26)

`config/paperclip/token-policy.json`의 `global_reserve.enabled: true`이면 기존 진입점이 `quota-switch.js`의 전 회사 제어기에 위임한다. 주간 사용 60%부터 절약, 70%부터 새 실행 중단으로 최소 30%를 보존한다. 15분 이내 주간 관측, 진행 중 예약, 모델별 예상 소비와 5%p 안전 여유를 포함하며 P0·CEO·PM 예외가 없다. 실제 CLI 실행 직전 공유 예약을 다시 확인한다.

중앙 제어기가 실제 공급자·모델을 다음 안전한 실행 경계에서 선택한다. 주간 한도나 구독 연결이 불명확하면 대기하며, 실행 중 작업·체크아웃과 운영자가 멈춘 에이전트는 보존한다. 공급자 전환 후에도 실제 작성 공급자와 다른 계열의 독립 검수와 기존 승인 조건을 지킨다. 토큰 수·환산 USD는 주간 %의 대체 측정값이 아니다.

중앙 제어기 이후 기존 순회는 장애·마커·막힘 점검을 계속 수행한다. CEO 점검의 하루 2회·4시간 간격 등은 순회 주기와 별도다. 루틴의 process 실행이 내부 LLM을 부르면 그 호출도 같은 신규 실행 승인 정책을 통과해야 한다.

## 중앙 정책 비활성 시 이전 관제 절차

아래는 이전 운영 절차의 기록이다. 중앙 정책이 활성일 때 모델·pause/resume·예약을 따로 변경하는 근거로 쓰지 않는다.

1. 구독 한도 창을 읽는다 — Claude(5시간 세션·주간), Codex(5시간·주간) — 페이퍼클립 `costs/quota-windows`.
2. 공급자별 상태를 정한다: GREEN / YELLOW(절약) / RED(필수만). 기준은 `config/paperclip/token-policy.json`.
3. 상태에 따라 조절한다
   - 파이프라인 엔진 순서(`workspace/ops/engine-routing.env`): 한쪽이 RED 면 다른 쪽을 앞에.
   - LLM 에이전트 모델: GREEN=기본, YELLOW=절약 모델, RED=다른 공급자로 전환(그쪽도 RED 면 일시정지).
   - 루틴: 2등급(주간 CMO·CEO)은 YELLOW 부터, 1등급(성장 매니저·경쟁 인텔)은 두 공급자 모두 RED 일 때 보류 — 풀리면 놓친 회차가 한 번 돈다.
   - 에이전트별 하루 비용 상한(환산 USD)을 넘기면 그 에이전트를 내일까지 일시정지.
4. 순회: 주인 없이 끝난 회차 마커를 마무리하고, 이슈가 없는 새 장애를 SRE 에게 연다. 한도가 풀리면 「한도로 보류」 이슈에 댓글로 깨운다.
   판단할 멈춘 이슈가 있으면 CEO 에게 `[막힘 점검]` 이슈를 연다(`triage.js` — 하루 2회·4시간 간격·새 항목일 때만).
   에이전트는 실행 중이면 멈추지 않고(끝난 뒤), 운영자가 다시 켠 날은 다시 멈추지 않는다.
5. 상태가 바뀔 때만 텔레그램 한 줄. 매일 21:00 리포트는 `job:token-report`.
