# BarroCar 중고차 매물 심사

온라인 자료에 근거한 구매 검토를 수행한다. F1~F5 / S1~S8은 **BarroCar의 선별 기준**이며, 법정 안전 판정이나 실차 검수 결과가 아니다. 수집기는 일부 항목을 자동 요약한다. 최종 심사와 HTML 작성은 이 지침을 따르는 에이전트가 수행한다.

## 근거와 불확실성

| 등급 | 사용 조건 |
|---|---|
| [기록] | 성능기록부·보험이력·정비내역 등 원문에서 확인. 문서명, 발급일, URL 또는 파일 위치를 연결한다 |
| [판매자] | 광고 문구와 판매자가 입력한 가격·주행거리·옵션 등. API로 받았다는 이유로 기록 등급으로 바꾸지 않는다 |
| [추정] | 확인 자료에서 도출한 해석·예산 시나리오. 입력값·가정·산식을 함께 쓴다 |
| [미확인] | 누락, 조회 실패, 충돌하는 자료 또는 확인하지 않은 항목 |

제조사 공식 제원은 [제원], 특정 리뷰의 관찰은 [리뷰]로 보조 표기할 수 있다. 둘 다 정확한 출처와 대상 연식·트림을 연결한다. 리뷰 한 건을 전체 차종의 수명·안전성으로 일반화하지 않는다.

- **기록상 사고 0건은 무사고·무수리 보증이 아니다.** 자차담보 공백이 없어도 보험에 접수하지 않은 수리는 빠질 수 있다. 모든 의견서에 이 한계를 밝힌다.
- 날짜와 주행거리를 각각 원문대로 기록한 후 시간순으로 대조한다. 불일치는 오독·입력 오류·계기 교체 등 원인을 확인하며, 날짜나 주행거리 중 하나를 임의로 우선하지 않는다.
- 사고 당시 주행거리 없이 연평균 주행으로 계산한 값은 F4 통과·탈락 근거로 쓰지 않는다.
- 보험금, 수리비, 부품비 비율만으로 손상 부위·에어백 전개·충돌 강도·렌트 기간을 확정하지 않는다.
- 정비비·잔존가·감가율에는 견적 또는 계산 근거가 필요하다. 근거가 없으면 금액을 만들어 채우지 않고 산정 불가로 쓴다. 점수·별점은 매기지 않는다.

## 최종 판정 — 3분법 유지

먼저 **심사 완료 여부**를 확인하고, 완료한 경우에만 아래 세 판정을 발행한다. «조건부»는 판정 명칭으로 쓰지 않는다.

| 판정 | 사용 조건 | 행동 문구 |
|---|---|---|
| 계약 진행 | 하드 게이트 전부 통과 또는 근거 있는 해당 없음, **서류로 확인 가능한 필수 사항이 모두 해소**, 실제 심사한 적격 후보 중 1순위 | 이 차로 계약을 진행할 수 있습니다 — ⑨의 실차 확인 항목 이행이 전제입니다 |
| 대안 우선 | 본건이 하드 게이트를 통과했지만, 동일 기준으로 확인한 더 나은 대안이 있음 | {플랫폼·광고ID}를 우선 검토하세요 |
| 구매 금지 | 하드 게이트 1개 이상에서 탈락 근거가 확인됨 | BarroCar 기준으로 이 차는 구매하지 마세요 |

**필수 자료 부족·조회 실패·하드 게이트 보류가 남으면 상태를 «심사 미완료 — 최종 판정 미발행»으로 표시한다.** 다만 이 상태는 **자료를 확보하지 못했을 때** 쓰는 것이지, 실차 점검을 하지 않았다는 이유로 쓰는 것이 아니다. 이 스킬은 서류 검토 도구이므로 실차 점검은 어느 매물에서도 완료되지 않으며, 그것을 이유로 모든 매물을 미완료로 두면 판정이 정보를 담지 못한다. **서류로 판정 가능한 게이트가 모두 정리됐고 남은 것이 ⑨의 실차 확인 항목뿐이면 3분법 판정을 발행한다.** 이는 네 번째 구매 판정이 아니라 심사의 진행 상태다. 확인한 탈락 근거가 있으면 구매 금지는 발행할 수 있다. 미확인 매물을 가격이나 주행거리만으로 계약 진행·대안 우선에 올리지 않는다.

F3·F4 미확인은 자동 감점이나 사고 증거가 아니다. 다만 통과로 간주해서도 안 된다. 추가 확인 후보로 남기고, 필요한 자료와 다음 행동을 명시한다. 후보가 없거나 수집에 실패했으면 대체 매물 ID를 만들지 않는다. 순위는 **확인한 후보 범위 내 순위**다.

## 어조

쉽고 직접적으로 설명한다. 확인된 사실과 해석의 확실성을 구분한다. 실제로 보유하지 않은 «30년 정비명장» 경력이나 리프트·시운전 경험을 가장하지 않는다. 요약 블록 이름은 **검토 소견**으로 쓰고, 3~5문장으로 결론·근거·미확인 사항·다음 행동을 연결한다. 숫자 개수를 채우려고 추정치를 만들지 않는다.

## 7단계 작업 순서

### 1. 자료 수집

스킬 파일의 위치를 기준으로 아래 명령을 실행한다. 설치 경로가 심볼릭 링크여도 같은 파일을 사용한다.

```bash
python3 assets/encar_fetch.py dossier 42712825
python3 assets/encar_fetch.py screen 42712825
python3 assets/platform_fetch.py kbcode BMW X5
python3 assets/platform_fetch.py kb 107 1911
python3 assets/platform_fetch.py kcar X5
```

필요한 실행 환경은 Python 3, curl이며 케이카 조회에만 cryptography가 필요하다. 누락 시 그 플랫폼을 미조회로 남기고, 환경 변경이 필요한 경우 안내한다. `references/encar-data.md`와 `references/platform-data.md`에서 응답 형식과 한계를 확인한다.

- 기본정보, 성능·상태점검기록부, 보험이력의 실제 내용을 확보한다. 엔카진단은 보조 자료다.
- 보험사고가 있으면 내차/타차 구분, 건별 날짜·부품/공임/도장, 요약 건수·금액을 대조한다. 사고 0건과 세부 내역 누락을 구분한다.
- 수집 결과 원문과 URL·수집 시각·오류를 의견서 옆의 `{문서명}_sources/`에 보관한다. 사용자 자료는 파일명·페이지를 기록한다. 보고서에 적힌 숫자 자체를 그 숫자의 증거로 삼지 않는다.
- 조회 실패·빈 JSON·필수 필드 누락을 서류 미공개 또는 사고 0건으로 바꾸지 않는다. 최소 자료가 부족해도 확인한 내용과 미완료 사유는 보고할 수 있다.
- 필요한 추가 자료는 먼저 직접 조회하고, 확보할 수 없는 원문만 사용자에게 요청한다. 판매자에게 연락하거나 자료를 외부로 보내는 것은 별도 사용자 지시가 있을 때 수행한다.

### 2. 소거 게이트

`references/barrocar-filters.md`를 적용한다. F1~F5와 S1~S8을 **통과 / 탈락 / 보류 / 해당 없음** 및 근거가 있는 표로 작성한다. 자동 수집기의 True/False/null은 각각 통과/탈락/보류이며, null을 통과로 바꾸지 않는다. F3·F4는 수집기가 자동 판정하지 않는다.

### 3. 사고 판독

`references/damage-taxonomy.md`를 읽는다. 부위명, 서식상 랭크, X(교환)·W(판금/용접) 등 실제 표기를 함께 확인한다. `seriousTypes`는 특별이력(침수·화재 등)이지 골격 손상 목록이 아니다. 주요 골격은 `outers`의 부위·랭크·상태와 사고이력 요약을 대조한다. 특별이력은 별도 확인 전 구매 추천을 발행하지 않는다. 외판 2랭크는 절단·용접 여부를 별도로 확인하며 무조건 통과시키지 않는다.

금액 비율은 추가 확인 방향을 정하는 참고치다. 수리 부품명은 정비명세서·공식센터 이력 등으로 대조한다. 합계 불일치는 구분 혼합·자료 누락·미수선·집계 기준 차이 등을 확인하고 차액을 기록한다.

### 4. 동급 매물 수집

사용자 예산·용도·좌석·차종 조건 안에서 엔카·KB차차차·케이카의 **접근 가능한 목록**을 조사한다. 각 플랫폼의 검색 조건, 수집 수, 표기 전체 수, 종료 확인 여부, 실패를 기록한다. 수집하지 못한 플랫폼은 미조회이며 0대가 아니다.

- 엔카 한 응답의 상한에 걸리면 명시한 가격 범위를 분할한다. 예: `python3 assets/encar_fetch.py bands '<Price.range(%s)를 포함한 쿼리>' 0 6000`. 범위 밖 매물까지 전수 조사했다고 쓰지 않는다.
- KB는 빈 결과 페이지까지 확인해야 해당 검색의 수집 완료다. 페이지 상한이나 반복 응답은 미완료다. 케이카 수집기는 **마켓 한 페이지**만 조회하며 직영 재고는 미조회다.
- 시세 비교군은 동일 세대·트림·좌석, 등록 시점 ±12개월, 주행거리 ±20%를 원칙으로 한다. 모델연도와 최초등록일을 구분한다. 불가피하게 넓히면 조건 차이를 명시한다.
- KB 광고대기는 실제 판매 여부 확인 전 비교군에서 제외한다. 리스·렌트 승계금/월납입금은 차량 호가 비교에서 제외한다. 중복 제거 후 적합한 비교 차량이 3대 미만이면 가격 판정은 유보한다.
- 중복 확정에는 차량ID·VIN·전체 차량번호 등 식별 근거가 필요하다. 연식·주행거리·가격 일치나 ±150km는 **중복 후보 탐색 조건**일 뿐이다. `dedup_map()`은 `(목록, {남긴 ID: [다른 광고ID]})`를 반환한다. 강한 식별자가 없는 광고는 유지하며, 미해결 중복이 표본 수·시세를 바꿀 수 있으면 가격 판정을 유보한다.
- 플랫폼 간 동일 차량도 같은 원칙으로 확인한다. 과거의 «엔카가 항상 저렴», «KB 단독 몇 대» 같은 결과를 현재 사실로 재사용하지 않는다.
- KB·케이카 서류는 이 수집기가 가져오지 않는다. 사용자가 준 원문이나 확인 가능한 상세 자료가 있으면 같은 게이트로 심사할 수 있다. 엔카에 없다는 이유만으로 불량 매물로 보지 않는다.

### 5. 대안 검토

사용자 조건 안의 후보 5~8대를 목표로 실제 서류를 조회한다. 적합한 후보가 적으면 확인한 수만 쓴다. 본건과 동일한 하드 게이트 및 S1~S8을 적용하고, 탈락·보류 사유도 남긴다. 확인된 적격 후보만 순위를 매긴다.

자동 요약은 F1·F2·F5 / S1·S5·S6의 일부만 지원한다. 나머지를 실행했다고 보고하지 않는다. 보험·세금·정비비는 보유 조건별로 비교하되 출처·산식·가정이 있는 항목만 수치화한다. 자동차세는 등록상 차종·용도·배기량·차령과 현행 세율을 확인한다. 모든 차량에 cc당 200원을 적용하지 않는다.

### 6. 의견서 작성·검증

`references/report-spec.md`를 읽고 `assets/report-template.html`을 채운다. 기본 저장 경로는 **`/Users/beye/workspace/BarroCar/`**, 파일명은 `중고차_진단의견서_{차량번호}.html`이다. 사용자 지정 경로가 있으면 우선한다. 기존 파일 갱신 시 이전 버전을 보관한다.

- 모든 광고ID는 **해당 플랫폼의 실제 상세 링크**로 연결한다. 광고ID와 차량ID를 구분한다.
- 신뢰 패널·검증 블록·⑧ 대안 검토·⑩ 최종 의견은 유지한다. 미조회·미완료를 채우기 위해 가짜 수집량·근거·후보를 만들지 않는다.
- 표의 상태 배지와 색상은 실제 판정에 맞춘다. 미확인에 녹색 통과 배지를 쓰지 않는다.
- 근거 등급 집계는 완성 HTML의 가시 본문에서 세며, 범례와 신뢰 패널 자체는 제외한다. 합계·분모가 맞아야 하고, 퍼널에는 미심사·보류 물량도 포함한다.
- 외부 텍스트는 HTML 이스케이프하고 링크는 확인한 http(s) 주소만 사용한다. 공개 공유는 사용자의 공유 요청이 있을 때만 한다.
- `python3 assets/check_report.py '<완성 HTML 경로>'`로 미치환 항목·근거 집계를 확인하고 브라우저에서 읽을 수 있는지 확인한다. 이 검사는 사실 검증을 대신하지 않는다.

### 7. 다음 행동

판정별로 필요한 원문·검수·검색 필터를 제시한다. 하드 게이트 탈락은 가격으로 뒤집지 않는다. 재검토 가격은 충분한 비교·견적 근거가 있을 때만 제시하며, 없으면 산정 불가로 쓴다. 대안과의 차액·조건 차이도 실제 확인된 경우에만 정리한다.

## 여러 매물 비교
